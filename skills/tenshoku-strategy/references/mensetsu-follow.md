# 面接後フォロー (Post-Interview Follow-up) — Evidence Checklist

Follow-up is a communication choice, not a hidden hiring lever. This reference makes no claim that a thank-you
message improves, harms, or predicts an outcome. Follow the invitation, the company's confirmed contact route,
and the user's preference.

## 1. Choose the channel

- Direct application: use the contact specified by the company. A short thank-you is optional.
- Agent route: send the user's factual feedback to the CA first unless the company explicitly provided a direct
  contact route.
- No contact route or unclear instruction: ask the company/CA to confirm the preferred channel. Do not guess.

Record the channel and the exact message as `Observed`. Do not treat a public anecdote or a crowd-sourced report
as company policy.

## 2. Thank-you template

Mention one real point from the interview and one true connection to the user's experience. Do not add a metric,
interest, or promise that the user did not provide.

```text
件名：本日の面接のお礼（氏名）

〇〇株式会社
〇〇様

本日はお時間をいただき、誠にありがとうございました。
面接で伺った【実際に話した内容】について、【自分の確認済みの経験】を活かして貢献できる点を
改めて考える機会となりました。
引き続き、どうぞよろしくお願いいたします。

氏名 / 連絡先
```

Send only after checking that every bracketed item is supported by the user's notes. The assistant must not
send it on the user's behalf.

## 3. When there is no response

Use the date and status in `data/pipeline.yml` rather than a universal cadence. Ask the documented contact:

- whether the application is still active;
- whether any additional information is needed;
- when the next update can be expected.

If the contact supplies a date, record it as an observed deadline. If no date is confirmed, keep it `Unknown`.
Do not infer rejection, enthusiasm, or an internal algorithm from silence.

## 4. Multiple processes

Do not contact the same company through multiple agents without the user's explicit plan. Keep each route,
message, and response in the pipeline history so duplicate outreach can be avoided. This is an execution record,
not a ranking or a probability model.
