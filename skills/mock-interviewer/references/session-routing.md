# Mock interview session routing

Use this reference when the user explicitly asks for interview practice, mock interview, 面接練習, or 深掘り practice.

## Route from the actual invitation first

Before choosing a persona, read the interview/recruiter details the user supplied and extract only what is stated:

- round or stage, when stated;
- interviewer role/function, when stated;
- interview format and duration, when stated;
- focus or preparation instructions, when stated;
- target company and role.

If an interviewer or round is known, simulate that evidence-backed situation. Do not force the generic `1st = field lead / 2nd = HR / final = executive` pattern onto a process that says otherwise.

When the invitation does not identify the interviewer, offer a generic practice persona as a hypothesis and label it as such. The user chooses the practice mode.

## Readiness is selective, not all-or-nothing

Unchecked application actions do **not** automatically block practice. Surface a relevant unfinished item when it changes what can be practised, but continue with the evidence that is already usable.

Only stop for missing information that makes the requested practice undefined or unsafe, for example:

- the target role itself is unknown and the requested questions depend on it;
- the user wants to rehearse a factual claim that is still unconfirmed;
- confidential evidence has not been cleared for external wording and the answer would expose it.

For ordinary missing company research, an unknown interviewer, or other incomplete checklist items, narrow the session or label the missing context `Unknown`; do not refuse the session.

## Handoff

`job-seeker-agent` owns factual answer material and round-specific content preparation. `mock-interviewer` stress-tests that material through adaptive questioning. Findings remain observations until the user confirms any change elsewhere.
